## Mechanics and compatibility boundary

Blizzard's [Forever Deep Dive recap](https://worldofwarcraft.blizzard.com/en-us/news/24303313) explicitly discusses rogue poisons benefiting from combined hit/critical-chance itemization. Its [Forever race/class overview, September 22](https://worldofwarcraft.blizzard.com/en-us/news/24304075) also identifies poison use as part of the rogue class. These are primary confirmation that poisons exist in Forever. Neither source publishes the poison crafting/application spell IDs, enchant IDs, spellbook representations, or the required per-weapon poison policy.

The actual Forever UI establishes a modern **multiple-coating weapon API** and modern secret/restricted aura contracts. It does not establish which enchant rows represent poisons. Community beta discussions describe charge-based poisons and poison/coating coexistence, but those reports were not used as implementation proof. No Classic poison IDs or Retail aura mechanics were transplanted based on them.

Consequently this build supports **Retail monitoring** and **experimental Forever diagnostics**. Forever warning evaluation remains explicitly unsupported. Its low interface number does not select an old unrestricted Classic aura path. Allowing the TOC to load on Forever is only enough to inspect the addon and capture the evidence needed for a real adapter.

For current Retail, Blizzard's [12.1 update notes](https://worldofwarcraft.blizzard.com/en-us/news/24293281/curse-of-ulatek-content-update-notes) confirm Atrophic Poison and Crippling Poison remain. The Atrophic duration change in those notes concerns its effect on the target; it is not evidence to change a player's coating duration. The local Retail tutorial identifies `315584` as Instant Poison (`AddOns/Blizzard_NewPlayerExperience/Blizzard_TutorialData.lua:237`). No primary source inspected here enumerates all current cast/aura IDs or establishes a new cast-versus-aura split. The existing poison catalog still needs the live all-spec checks described below.

## Diagnostic implementation

`ClientDiagnostics.lua` returns only bounded sanitized strings. It checks tables before reading or iterating them, checks each field before formatting it, never stringifies inaccessible values, and never modifies Blizzard-owned data. It reports build/project/class/spec and API capabilities. Forever multi-enchant samples use the actual enum hand slots, at most eight rows each, and include enchant IDs, types, milliseconds, charges, and icons without interpreting any row as a poison.

Sampling is skipped during loading, combat, active/activating restrictions, or unavailable restriction checks. This is deliberately conservative for an on-demand diagnostic read. Known Classic poison spell IDs are omitted because this investigation did not verify them; presenting a guessed list as learned-spell evidence would be misleading.

`ClientDiagnosticsTests.lua` uses private fixtures and an injected addon-owned adapter. Nine focused checks cover slot enums, multiple coatings, inaccessible tables/fields, restrictions and failed queries, bounded output, text sanitization, invalid numeric slots, and class/spec availability. They do not monkeypatch any Blizzard global or live addon adapter, and they do not simulate the engine's actual taint provenance.

Custom audio now selects pre-attenuated OGG assets from `sounds/` at the saved 5% increments. `scripts/build_sounds.py` generates these from the untouched original WAV files. This avoids temporary writes to a shared sound-channel CVar, while retaining the game's own Master volume behavior. All 40 variants must be included in any eventual addon package. Hearing the chosen volume levels in the client remains a live check.

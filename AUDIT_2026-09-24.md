## Findings and corrections

| Area | Finding | Resulting behavior |
| --- | --- | --- |
| Aura restrictions | `GetPlayerAuraBySpellID` can return no values when a `RequiresNonSecretAura` restriction blocks it. The old implementation interpreted that as an absent poison. | Check spell-specific secrecy before querying; gate foreign values and tables before use. API failures and incomplete scans become unknown, hide stale warnings, and quietly rebaseline audio. No secret aura fields are formatted or cached. |
| Poison identity | The legacy fallback matched localized names and stopped at 40 auras. Current exports no longer provide `AuraUtil.FindAuraBySpellID`. | Prefer direct player spell-ID lookup; use a bounded single indexed snapshot only if direct lookup is absent. Legacy fallback uses the spell-ID return rather than names. |
| Learned poisons | The old requirement was always one/two of each category, even when a character had not learned enough poisons. Legacy spell-known globals are optional/deprecated. | Prefer authoritative `C_SpellBook.IsSpellKnown`; cap requirements by learned category choices. Unknown spell/talent knowledge cannot produce a missing warning. |
| Spec transitions | Scanning only currently known poisons missed an active poison retained across a spec change. | Observe the complete existing poison catalog; offer only learned, inactive choices in the HUD. Copy validated known/active IDs and Dragon-Tempered Blades state into diagnostics. |
| Startup audio | Arming depended on a later event; the first actual expiry long after login could become a silent baseline. | Schedule the baseline at the end of the startup delay. Replacement, disable/re-enable, loading, and logout invalidate old callbacks. |
| Loading/lifecycle | Loading could leave old missing state visible; stale callbacks and restricted observations could create misleading audio transitions. | Clear loading/disabled HUD state, bind deferred work to its lifetime, and suppress transitions across unknown/ineligible intervals. Player-filtered aura/inventory events and restriction/revival/equipment refreshes keep observations current. |
| Edit Mode boundary | HUD code invoked Blizzard Edit Mode dirty-state methods and borrowed its selection implementation. Permanent hooks could run after disable. | Preserve Blizzard Edit Mode discovery through public Enter/Exit notifications, with an addon-owned preview and Save, Cancel, Revert, and Reset controls. `/np edit` remains a standalone entry point. It refuses restrictions and cancels unsaved work on combat, loading, disable, and logout. This removes a taint risk; no engine taint fault was independently reproduced. |
| UI teardown/settings | Drag callbacks and edit sessions could outlive their settings context; malformed anchors/scales could reach frame setters. | Bind edits/options to their originating database, reject stale writes, validate finite numbers and anchor points, and stop dragging/restore unsaved previews during teardown. Logout avoids new poison reads. |
| Sound | Alerts temporarily changed a shared channel CVar, with delayed restoration that could overwrite user changes or survive disable/logout. The slider also saturated at 50%. | Select one of 40 bundled OGG variants at 5% increments. Each slider now covers 0–100%, respecting Master volume. No sound CVar writes, volume locks, or audio restoration timers remain. |
| Tests/diagnostics | The original 13 tests covered only helpers and aborted at the first failure. There was no useful compatibility capture. | 113 isolated regressions, failure-continuing runner, reverse-order checks, startup simulations, bounded diagnostics and a copyable report. |

The code uses addon-owned state and public Settings registration. Access/forbidden/protection checks precede frame mutation. Restricted editor work is refused or retried after events. Ordinary rendering uses unprotected addon-owned frames. `pcall` contains errors; it is not treated as a taint barrier. No Blizzard globals, API tables, mixins, or secure delegates are monkeypatched by runtime code or in-game tests.

## Forever viability

**Poisons exist, but monitoring is not implemented speculatively.** Blizzard's [Forever Deep Dive](https://worldofwarcraft.blizzard.com/en-us/news/24303313) confirms rogue poison mechanics. The actual export supplies modern restrictions and a multiple-row `C_Item.GetWeaponEnchantInfo(Enum.WeaponSlot)` API. Its `Temporary`/`Imbue` enum does not identify poisons, and the legacy global only exposes one temporary enchant per slot. Neither Retail's aura catalog nor a generic "any enchant present" check establishes poison coverage.

Forever therefore loads the editor, settings, tests, and diagnostics, while the monitor reports **unsupported** and issues no poison alerts. A one-time message makes that limit visible. Diagnostics sample at most eight enchant rows per hand outside loading/combat/restrictions, preserving accessible IDs, types, charges and milliseconds without classifying them. Source contracts and the remaining mechanics questions are in [CLIENT_RESEARCH_2026-09-24.md](CLIENT_RESEARCH_2026-09-24.md).

A viable next adapter would map observed poison enchant IDs/ranks, learned recipes/items and equip/charge/expiry behavior, then evaluate a verified per-weapon policy. It must retain Forever's modern secret-value guards. Do not equate its low interface number with unrestricted Classic APIs.

## Follow-up: restore native Edit Mode discovery

The initial audit removed the entire integration more broadly than the evidence required. The beta.2 follow-up restores opening Edit Mode, dragging NoPoizen alongside other HUD elements, and clicking its preview for settings. The preview stays editable after NoPoizen Save/Cancel; closing Edit Mode cancels only unsaved NoPoizen work. Standalone `/np edit` retains its existing behavior.

`EditMode.lua` subscribes to `EditMode.Enter` and `EditMode.Exit` using the public EventRegistry API and a primitive string owner. It does not write to Blizzard manager state or register NoPoizen as a Blizzard system. Read-only, access/forbidden-guarded `IsEditModeActive` handles enabling while Edit Mode is already open. Disable/logout unregister callbacks and invalidate old callback generations; partial registration rolls back, and unavailable/restricted registration can retry. Loading/combat cancellation does not resurrect the editor.

Verified contracts in both local exports: `Blizzard_EditMode/Shared/EditModeManager.lua` emits Enter/Exit; `Blizzard_SharedXMLBase/CallbackRegistry.lua:112,184,225` defines callback registration, owner-first dispatch, and removal. No additional addon dependency was needed. Eleven new private-fixture regressions and the updated Retail/Forever startup simulations cover the bridge; the offline manager fixture rejects all writes to its state.

**Live check:** reload beta.2, open Blizzard Edit Mode, drag NoPoizen, click it, change scale, and use **Save in NoPoizen's panel**. Close and reopen Edit Mode to confirm persistence. Change it again without saving and close to confirm rollback. Repeat disable/re-enable while Edit Mode is open, combat interruption, and `/np edit` outside native Edit Mode. Blizzard's own Save/Revert buttons govern Blizzard layouts; the NoPoizen panel labels its independent Save behavior. Actual client UI/taint validation remains pending.
